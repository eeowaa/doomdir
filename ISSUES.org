** Attributable to WSL 1 performance issues [3/3]
*** OKAY Staging hunks from the Magit status buffer is slow :perf:
_Problem_
- It takes multiple seconds to stage hunks from the Magit status buffer

_Remediation_
- *Configure Magit status refresh to improve performance*
  - Removed automatic =diff-hl= updates when refreshing Magit
    - Shaves ~1 second off from Magit status refresh
    - Toggle =diff-hl= off/on again to refresh fringes (=SPC t v= twice)
  - Removed automatic Magit status buffer updates from other Magit commands
    - Improves performance of per-file Magit operations
    - Force a refresh from the Magit status buffer via =C-l=
- *Use the status buffer while avoiding unnecessary refreshes*
  - Select multiple hunks with =v= before applying a Magit operation
    - Performs a single status refresh instead of one per hunk
    - Only works with subsequent hunks (out-of-order hunks cannot use this)
    - Point must be on the header line of the hunk (not in the middle)
  - Stage hunks by opening per-file =magit-diff= buffers
    - Avoids Magit status refresh, but still need to wait for diff refresh
    - Diff refresh is pretty fast for single-file diffs
    - For a given file under point in the status buffer:
      - =d -- RET u= replicates the "Unstaged changes" section
      - =d -- RET s= replicates the "Staged changes" section
      - =d -- RET w= diffs the worktree against HEAD
    - Same comfortable diffing interface as the Magit status buffer
  - Stage hunks by opening per-file =magit-ediff= buffers with =e=
    - Performs a single Magit refresh after all changes have been finalized
    - The interface feels a bit clunky (3-way diff) but it is the most efficient
    - Can be used to replicate =add=, =reset=, and =checkout= commands
      - =ab= applies HEAD to the index (/unstages/ the hunk like =git reset -p=)
      - =ac= applies HEAD to the worktree (/discards/ the hunk like =git checkout -p HEAD=)
      - =bc= applies the index to the worktree (/discards/ the hunk like =git checkout -p=)
      - =cb= applies the worktree to the index (/stages/ the hunk like =git add -p=)
    - Unfortunately, the 2-way diff ~magit-ediff-show-*~ commands do not allow edits.
      If they did, the following commands would be especially useful and easy to use:
      - ~magit-ediff-show-staged~ (=E i RET=) to unstage hunks
      - ~magit-ediff-show-unstaged~ (=E u RET=) to stage/discard hunks
      - ~magit-ediff-show-working-tree~ (=E w RET=) to discard hunks
- *Use Magit while avoiding the status buffer*
  - Open per-file =magit-diff= buffers via =SPC g . D u/s/w=
  - Open per-file =magit-ediff= buffers via =M-x magit-ediff-stage RET RET=
  - Navigate between and stage hunks in a file via =SPC g ]/[/s=
  - Use =SPC g /= to open Magit dispatch (like =h= from Magit status)
- *Fall back to Git CLI from =vterm=*
  - Use =git add -p= to selectively stage
  - Use =git reset -p= to selectively unstage
  - Use =git checkout -p= to selectively discard

*** OKAY Git lockfile contention during Magit rebases :perf:
_Problem_
- Sometimes rebases fail from Magit due to lockfile contention
- Hard to unstick the problem within Magit or even the Git CLI
- Git itself seems to get confused

_Remediation_
- Perform rebases via the command line in =vterm=:
  #+begin_src sh :eval no
  # Add to <commit> but keep original message
  git commit --fixup=<commit>

  # --OR-- Add to <commit> and merge <message> with original message
  git commit --fixup=amend:<commit> -m <message>

  # --OR-- Keep <commit> but replace original message
  git commit --fixup=reword:<commit> --allow-empty -m <message>

  # Perform rebase (--autostash and --autosquash already applied per config)
  git rebase -i <commit>^
  #+end_src
- Resolve any conflicts in Magit per usual
